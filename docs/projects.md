# Proyectos personales

Estado al 19 oct 2026: CRUD y gRPC-Web publicados. Según el relevo del propietario, guardar, abrir, renombrar y borrar funcionan con su cuenta en producción; las tres migraciones fueron aplicadas por él. Esa comprobación no se repitió en esta entrega. No se anuncian guardados sin respuesta del servidor.

La sección propia `/projects` aplica la maqueta A elegida por el propietario: tres tarjetas por fila en escritorio, dos en tabletas y una en móvil. Barra/menú muestran Proyectos con sesión; Perfil mantiene un enlace. Sin sesión, la ruta ofrece entrar/crear cuenta y conserva el retorno a Proyectos. Analizar y Alinear conservan guardado explícito por nombre, actualización, copia, desvinculación y recuperación confirmada.

Cada tarjeta muestra evidencia disponible: prefijo de hasta 40 residuos (no una estructura), longitud, masa/pI/GRAVY guardados, procedencia exacta y fecha relativa localizada con fecha absoluta accesible. Si hay comparación, muestra sus longitudes/prefijos y conteos convertidos a porcentajes, matriz y modo. Un resultado ausente no aparece como cero. Proyectos mixtos ofrecen Analizar y Alinear; una comparación sin secuencia activa abre Alinear. Abrir reemplaza entradas/ventana/comparación tras confirmación; propiedades se recalculan en Worker. Solo resultados vigentes salen del navegador. Máximos: 120 caracteres de nombre, 100.000 residuos en análisis y 5.000 por entrada de comparación.

Buscar por nombre (substring literal, sin distinguir mayúsculas) y ordenar por recientes/nombre operan sobre toda la colección en SQL, antes de paginar. No se filtra solo la página cargada. Token opaco ligado a consulta/orden; búsqueda nueva reinicia la página. `query_applied` detecta un backend antiguo que ignora estos campos y evita presentar una respuesta sin filtrar como búsqueda correcta. Su listado por defecto todavía puede abrirse con tarjeta sin preview.

El menú de cada tarjeta permite renombrar, duplicar y eliminar. Los diálogos contienen el foco, Escape cancela y devuelve el foco al origen; borrar enfoca inicialmente Cancelar. Renombrar verifica la versión antes del PUT. Duplicar abre el snapshot seleccionado y crea otro proyecto, sin sustituir secuencias/borrador, proyecto activo ni puntero. Una creación incierta no se reintenta automáticamente. Tras escritura confirmada se reinicia el listado para conservar orden/filtro; si falla solo esa recarga se conserva el éxito de escritura y se muestra el fallo de actualización.

El último ID se guarda por propietario en localStorage; no se almacenan allí secuencias ni resultados. Tras recargar se consulta la API con JWT. Una sesión nueva con borrador existente no lo reemplaza automáticamente. Cambiar de cuenta cancela peticiones e ignora respuestas anteriores. Guardar mientras se edita conserva los cambios recientes como pendientes. 409 no actualiza la versión local: copiar o recuperar explícitamente. Antes de reintentar una creación tras timeout, actualizar lista, porque el servidor pudo recibirla. No hay sincronización offline ni guardado automático.

Contrato backend: `../backend/docs/project-persistence.md` y `../backend/docs/api.md` desde el workspace. Tablas projects/analyses existentes y funciones SQL SECURITY INVOKER; sin service_role. La evidencia original del 12 oct incluye PostgreSQL 18 temporal con RLS/concurrencia y Python 3.13 con API simulada. La aplicación remota de las migraciones y la prueba del propietario son posteriores; no certifican Python 3.14 ni aislamiento entre dos cuentas reales.

Pruebas de cliente: snapshot vigente/desactualizado/validación, microsegundos/204/409/esquema incompatible, reapertura, edición durante guardado, cambio de cuenta y cancelación. E2E de CRUD/recarga/conflicto/restauración y 360/1280, claro/oscuro, teclado, 44 px, AA y movimiento reducido con Auth/API simuladas. No demuestra una sesión o base remota.
